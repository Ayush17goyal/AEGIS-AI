## Architecture conflicts and approved crypto primitive

Architecture v2 selects NeMo + Laya input, Python policy (ALLOW/MASK/BLOCK/APPROVAL), approved privacy transformations, preauthorized retrieval, real LLM, Regex + Presidio output, minimal audit and `/health` + `/v1/chat`. Older PRD/phases/memory advertise custom input regex/entropy/normalization, LLaMA decisions, dashboard/Scenario Lab, extra admin endpoints, sentence fingerprints, hash chains, vault/restoration and completed phases. Those statements do not override the user's selected v2 architecture. SQLite remains allowed for prototypes; PostgreSQL is the target. Laya contract, actual provider, role/resource matrix, thresholds, approval semantics and reversible token lifetime remain open decisions rather than invented features.

This task adds only a recoverable AES-256-CCM primitive in `backend/encryption.py`: env-only `AEGIS_VAULT_KEY`, strict base64 decoding to exactly 32 bytes, fresh random 13-byte nonce, 16-byte tag appended to ciphertext, canonical domain-separated AAD binding key ID and purpose. Decryption requires the caller's expected key ID/purpose, authenticates before returning bytes and rejects tampering/wrong keys. Maximum plaintext is 65,535 bytes for the selected CCM nonce size. No plaintext/key logging, persistent vault, DB migration, automatic restoration, key registry or integration into existing storage was added. **Existing DB content is not encrypted by this change.** The module is independent of DB/provider imports. Key rotation/registry remains a caller/deployment concern.
